02 — 五模块认知诊断 / FIVE-MODULE COGNITIVE DIAGNOSIS

五个模块,
一次全面尸检。

AgentDebug 对输入的全部 step 执行拆分与 Phase 1 检测——不使用候选窗口,不抽样。静态脚本产出事实,语义核查补足上下文,模块允许留白,但留白本身永远不会被误判为根因。

M1Memory记忆 · 召回与约束保持

核查 prior facts 与相邻步骤,追踪记忆读写链路。

  • hallucination · 幻觉注入
  • recall_failure · 召回失败
  • constraint_forgotten · 遗忘用户约束
  • oversimplification · 过度简化

  • misread_tool_result · 误读工具结果
  • false_success_claim · 假成功声明
  • missed_test_failure · 漏掉测试失败
  • premature_completion · 过早完成

M0允许留白BLANK ≠ ERROR

Memory / Reflection / Planning / Action 任一模块都可能无信号——留白模块不是错误,系统绝不会因空模块本身而认定根因,也不会从 Action 失败反推 Planning 必然失败。

03 — 三条互斥路线 / THREE MUTUALLY-EXCLUSIVE ROUTES

同一引擎,
三条路线。

不同的问题深度,对应不同的执行代价。普通追问永不重复运行五模块;定向查因只执行命中的专项诊断器——每一分钱都花在刀刃上。

04 — 一键诊断流水线 / ONE-CLICK PIPELINE

七步流水线,
零二次运行。

同一次一键诊断只允许启动一次 Agent。core findings 一旦冻结,专项阶段只能无损追加 supplementalEvidence——已确认的根因永远不会被后续阶段改写或删除。

05 — 专项诊断器 / SPECIALIZED DETECTORS

诊断器自注册,
平台零感知。

服务端不维护任何诊断器名单,也不内置诊断器业务规则。在 detectors/*/detector.json drop 一个清单,公共 runner 自动完成发现、关键词匹配与执行。

① 写清单 detector.json声明名称、版本、模式与意图关键词
② 写脚本 detect.py只产出 facts / anchors / details 结构化事实
③ 放入 detectors/ 目录runner 扫描自注册,即刻可被一键与定向路线调用
